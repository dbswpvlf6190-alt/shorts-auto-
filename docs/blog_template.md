# 블로그 글 포맷 (원소스 멀티유즈 1호, 2026-08-22 확립)

PROJECT_CHARTER.md 5번(하나의 주제를 여러 콘텐츠로 확장) 항목의 첫 구현. 이미 숏츠용으로 조사·작성된
`script.txt`/`meta.json`을 재료 삼아, 검색 유입을 노리는 블로그 글로 확장한다.

**이 단계는 완전자동이 아니다.** 글쓰기 품질(문단 구성, SEO 제목, 공감 도입부)은 세션에서 Claude가
직접 작성해야 하며, 무인 스크립트가 LLM API를 호출해 자동 생성하게 하려면 별도 API 키/비용 결정이
필요하다(보안 원칙 9번 — API 사용량·비용 관리). 지금은 "사용자가 큐 아이템을 지정하면 그 세션에서
블로그 글을 써서 `input/queue/NN_이름/blog_draft.md`에 저장" 하는 반자동 방식으로 시작한다.

## 구조

```
# (SEO 키워드가 들어간 제목 — 검색어를 그대로 쓰듯이)

(도입부 2~3문장: 이 글을 검색해서 들어올 사람이 처한 상황을 먼저 짚어준다 — 숏츠 훅과 같은 역할)

## (핵심 개념 설명 소제목)
(개념을 풀어서 설명. 숏츠 대본의 핵심 문장을 확장해서 씀)

## (실전 확인/대응 방법 — 체크리스트 형태)
1. ...
2. ...

## 자주 묻는 질문
**Q. ...**
A. ...

## 정리
(요약 2~3문장 + 채널 CTA: "매일 부동산·재테크·정책 정보는 @daily.factlab 쇼츠로 정리해드립니다")

---
**태그:** #키워드1 #키워드2 ...
```

## 주의사항
- 숏츠 대본을 그대로 복붙하지 말 것 — 블로그는 검색 유입이 목적이라 숏츠보다 훨씬 길고 구체적이어야 함(실전 방법/절차/근거 추가)
- 제목은 실제 사람들이 검색할 법한 문구로 (예: "선순위 임차인 확인 방법", "전입세대열람원 발급") — 숏츠 훅 문구를 그대로 쓰지 않음
- 마지막엔 항상 채널 CTA로 숏폼 콘텐츠와 연결 (블로그 → 채널 유입 구조)
